# 异常诊断与自动恢复

JobClaw v2.2.0 将异常分为“自动处理”和“需要用户确认”两类。目标是让普通页面波动不再打断整条投递队列，同时避免未知发送结果造成重复沟通。

## 自动处理

以下异常默认不触发全局熔断：

- 单个岗位已关闭、沟通入口未加载或页面响应慢
- 地区、求职类型、薪资、经验或学历筛选未生效
- 临时网络超时、AI 服务或企业查询 Provider 不可用
- BOSS 页面脚本失去连接
- 平台短时频率限制

系统会按异常类型执行：

```text
重新连接页面
→ 必要时重新打开职位页
→ 指数退避或降低节奏
→ 降级到本地模型/轻量算法/本地风险规则
→ 冷却或跳过当前岗位/搜索组合
→ 从断点继续
```

自动恢复达到配置次数后，普通筛选或网络异常会跳过当前搜索组合继续下一个；持续限频会自动延长冷却时间，不要求用户反复重置。

## 必须用户确认

以下情况不会自动绕过：

- 验证码、安全验证或账号限制
- 登录状态失效
- 当前 HR、公司或岗位身份与目标任务不一致
- 已尝试发送但无法确认聊天气泡是否出现

侧栏会显示原因和处理建议。用户完成处理后点击“已处理并继续”，任务从保存的进度恢复。

## 统计与日报

首页和 OpenClaw 日报会展示：

- 今日目标、已完成和剩余数量
- 自动修复次数
- 自动跳过次数
- 需要人工处理次数
- 重复、风险、低质量和筛选失败数量

每日目标是调度目标，不是绕过平台安全机制的硬性承诺。验证码、平台限频、当天有效岗位数量和用户筛选条件都可能影响实际完成量。

## 建议设置

默认设置适合多数用户：

```text
异常自动恢复：开启
最大尝试次数：3
基础等待：45 秒
每日目标：150
```

频繁出现限频时应使用标准或保守节奏，不建议通过缩短间隔对抗平台限制。
